1. The Imbalance Trap

In fraud detection, standard intuition about machine learning fails. Around 98.3% of transactions are benign and only 1.7% are fraud.

Mental Model: If a doctor diagnoses every patient as "healthy", they are 99% accurate, but cure 0 diseases. Accuracy is meaningless when the target event is rare.

2. Why Raw IDs Break Your Model

Look at your columns: customer_id, merchant_id, device_id. Why can't we feed them directly to LightGBM?

  • Overfitting: The model memorizes that ID C_1042 was once fraudulent and blindly flags it forever.
  • Cold Start Problem: Test data contains brand new customers never seen in training. The tree has no split rule for unseen strings.

The Fix: Convert IDs into behavioral summaries (e.g. "Has this customer logged in from 4 new devices today?").

3. The Golden Rule: Strictly-Prior Features

When calculating an entity's past history (e.g., average transaction amount), you must not include the current row or future rows.

# Vectorized leak-safe trick in src/features.py:
cum_sum = grp.cumsum()
prior_sum = cum_sum - df['amount_bdt']  # Subtract current row!
prior_count = grp.cumcount()            # 0-indexed, naturally excludes current row
